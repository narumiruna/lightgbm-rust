## LLVM libc++ sorting order

The checked AUC-mu sorting routine in `src/metric/discrimination.rs` is translated from the LLVM libc++ sorting algorithm used by the pinned Apple clang reference. The source file and header identities are recorded in `tests/fixtures/metric_edges.json`. LightGBM's epsilon comparator is not a total order; passing it to Rust's standard sort can panic on finite inputs. The checked routine preserves the reference ordering without unchecked pointer access.

LLVM source headers state that they are part of the LLVM Project and use this license. The remaining original project code is MIT-licensed unless a source notice states otherwise.

## Isolated reference dependencies

The reference build uses pinned Eigen (MPL-2.0-only subset selected by `EIGEN_MPL2_ONLY`), fmt (MIT), fast_double_parser (Apache-2.0 or BSL-1.0), and nanoarrow (Apache-2.0) submodules. Their exact Git identities are recorded in `docs/reference-manifest.json`. The CPU build does not fetch or use Boost.Compute. These dependency sources and compiled libraries remain in ignored `references/` and `target/oracle/`; they are not copied into the Rust product or fixture distribution. This notice does not replace their licenses if their code is later redistributed.

The isolated Python dependency versions and distribution hashes are in `tools/oracle/uv.lock`. They are developer dependencies, not product dependencies. No installed LightGBM wheel is used. scikit-learn 1.6.1 (BSD-3-Clause) is used only by the original Python CV workflow for stratified and group-safe folds. Standard shuffled CV uses NumPy RandomState and the original engine aggregation uses NumPy population standard deviation. Package distribution hashes remain in the oracle lockfile. No scikit-learn code, native numerical dependency, or Python dependency is added to the Rust product.
